## Comparison with the Humble baseline (2026-08-06)

Same two cameras (serials 24057131 / 24057132), same 40 fps single-camera protocol, same
10-minute duration. What changed underneath: Ubuntu 22.04 → 24.04, ROS 2 Humble → Jazzy,
generic kernel → 6.8.1-1057-realtime with `isolcpus=4,5,10,11`, and MCAP went from an
explicitly selected storage plugin to Jazzy's default.

| Metric | Humble (20260806) | Jazzy (20260810) |
|---|---|---|
| Measured rate | 39.99 ± 0.0 Hz (100.0%) | 39.99 ± 0.0 Hz (100.0%) |
| Drops | 0 | 0 |
| Total frames | 23972 | 23967 |
| CPU mean | 125.9% | 110.6% |
| CPU peak | 152.9% | 150.1% |
| Memory peak | 755.6 MiB | 905.4 MiB |
| Bag size | 26368.8 MB | 23816.8 MB |

The metrics that gate acceptance — rate and drops — are identical, which is the result that
matters: the Jazzy migration costs nothing on the camera path.

The secondary numbers moved and none of the movement is interpretable as a regression. Bag
size is scene-dependent because Zstd compresses image content, and the two runs filmed
different scenes, so a 10% difference says nothing about the stack. Memory is higher and CPU
lower, which is consistent with different buffering behaviour, but with one sample per
configuration neither is evidence of anything. Treat rate and drops as the comparison and the
rest as recorded context.

Note the CPU percentages are of a single core (Docker convention), measured on a host with
four of twelve logical CPUs isolated away from general scheduling.
