# ESU-TAP v2 — energy path, lease, takeover, bypass and link loss, 2026-11-03

> **Role: measured numbers (layer 4).** One measurement session. Immutable once committed.
> Module doc `docs/modules/esu.md`; design decision 18 (amendment 2026-11-03).

**Result.** With the ESU on (10 W, no instrument), a software command activated CUT, COAG and
bipolar; the pedals activated all three through the powered board and **with the board
unpowered** (the bypass). A software output that was no longer renewed opened **503.1 ± 3.8 ms**
after its last renewal (n = 8, 497–508 ms; firmware lease 500 ms). A bipolar pedal press during
software CUT released CUT as a takeover and closed bipolar **11 ms** later, and the board
refused further software renewals. Killing the micro-ROS agent during software CUT ended the
ESU's activation; the board came back disabled with all outputs open. A board message reached
a Fast DDS subscriber 0.07–1.07 ms after the agent read it from USB (n = 17).

## Method

- **Commands** went straight to the board's services from a Fast DDS client (`tools/cut_hold.py`,
  `tools/fault_tests.py`): enable (`/esu/arm`), ON on one channel renewed every 100 ms for the
  stated hold, then the renewals stopped **without** an OFF, so the board's lease ended the
  output. Times are the client's: "last renewal" = the last acknowledged renewal, "open" = the
  receipt of the board's state message with the channel open.
- **ESU response** was observed by the operator at the ESU (activation tone and indicator), not
  timed. Contact closure was checked with a continuity meter on the ESU-side monopolar plug for
  CUT only (pins 1–2), before the meter's battery failed.
- **PC path** (session 2): agent at verbosity 6 logs each serial message and each DDS write with
  µs timestamps; one CycloneDDS and one Fast DDS listener print receipt times at 1 ms
  resolution (`tools/esu_watch.py`). Pedal presses by the operator.
- **Late-joining subscriber**: listeners started after the publisher had already published
  (`tools/late_pub.py`, `tools/idle_sub.py`, domain 74, no board; `tools/state_watch.py` on the
  board); one press, or one sample after a 40 s idle, then the timing of the first new sample.

## Results

### Energy at the ESU (operator-observed)

| Test | CUT | COAG | bipolar |
|---|---|---|---|
| Software pulse, 2 s of renewals (lease end included: 2.5 s) | activated | activated | activated |
| Pedal through the powered board | activated | activated | activated |
| **Pedal with the board unpowered** (barrel and USB unplugged) | activated | activated | activated |

After power was restored (barrel, then USB, no pedal held) the board rejoined the agent by
itself: boot id 16, disabled, outputs open.

### Lease: last renewal → board reports the output open

| Run | Hold | ms |
|---|---|---|
| CUT, ESU unplugged, meter on pins 1–2 (beeped for the hold) | 30 s | 506 |
| COAG, ESU unplugged | 30 s | 503 |
| bipolar, ESU unplugged | 45 s | 508 |
| COAG, ESU unplugged | 120 s | 505 |
| bipolar, ESU unplugged | 120 s | 506 |
| CUT, ESU on | 2 s | 499 |
| COAG, ESU on | 2 s | 501 |
| bipolar, ESU on | 2 s | 497 |
| **all** | | **503.1 ± 3.8 (497–508), n = 8** |

ON acknowledgement → board reports the output closed: 7–8 ms (n = 8).

### Faults, ESU on

| Test | Board messages (s) | Operator |
|---|---|---|
| Surgeon takeover: software CUT on, bipolar pedal pressed | 641.581 CUT open, source takeover; 641.592 bipolar closed, source pedal (**11 ms**); next two CUT renewals refused; 644.082 bipolar open (pedal released); then enable = false, outputs 0 | CUT tone stopped, bipolar tone for the press |
| Link loss: software CUT on, agent SIGKILLed 4.06 s after CUT closed | (no messages while the agent was down); after the agent restarted: enable = false, outputs 0, boot id 16 | CUT tone stopped by itself about 0.5 s after the kill |

| | |
|---|---|

### Late-joining CycloneDDS subscriber, first new sample

| Writer | Fast DDS writer heartbeat | Delay of the first sample |
|---|---|---|
| Board, via the agent (2 presses) | default (3 s) | 3.0 s (the press arrived together with its release) |
| `rmw_fastrtps_cpp` publisher, no board | default | 3.001 s |
| `rmw_fastrtps_cpp` publisher, no board | 100 ms (`tools/fastdds_hb.xml`) | 0.101 s |
| esu node `/esu/state`, board | 100 ms (`arts_esu/config/fastdds_esu.xml`) | 0.101 s |
| Board raw topic via the agent, same press | profile set, not applied by the agent | 3.000 s |

A Fast DDS subscriber received every one of these on time. A CycloneDDS subscriber that joined
before the publisher's first sample received 12 of 12 samples on time after idles of 10–300 s.
Every sample after the first was on time.

Not measured: RF output or its timing at the ESU; COAG and bipolar contacts by meter; a hung
controller, stuck drivers or contacts, sense faults.
